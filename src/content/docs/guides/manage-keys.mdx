This page describes polyjose 0.1.2.

polyjose works with keys as JSON Web Keys (JWK, [RFC 7517](https://www.rfc-editor.org/rfc/rfc7517)). In JavaScript a JWK is a plain object or its JSON text, in Kotlin and Swift it is JSON text, and in Rust it is a `jwk::Jwk`. Every key is validated when it is used: a point off its curve, a key of the wrong length or a malformed member fails before any cryptography runs.

## Generate keys

Generated keys come from the operating system's random number generator. If it isn't available, generation fails with `RandomnessUnavailable` and returns no key.

- `jwkGenerateOct(length)`: a secret `oct` key of `length` bytes ([RFC 7518 §6.4](https://www.rfc-editor.org/rfc/rfc7518#section-6.4)).
- `jwkGenerateEc(curve)`: an EC private key on `P-256`, `P-384`, `P-521` ([RFC 7518 §6.2](https://www.rfc-editor.org/rfc/rfc7518#section-6.2)) or `secp256k1` ([RFC 8812 §3.1](https://www.rfc-editor.org/rfc/rfc8812#section-3.1)).
- `jwkGenerateOkp(curve)`: an `Ed25519` signing key or an `X25519` key-agreement key ([RFC 8037 §2](https://www.rfc-editor.org/rfc/rfc8037#section-2)).

In Rust, `keys::generate` takes a `keys::KeySpec`. RSA keys can't be generated (see [Not supported › RSA private keys](/security/not-supported/#rsa-private-keys)).

<Samples id="manage-keys/generate" />

`jwkGenerateForAlg` (`keys::generate_for` in Rust) picks the key type for a JWS `alg`, a JWE `alg` or an `enc`, and sets the key's `alg` member, so the key can't be used with any other algorithm ([RFC 7517 §4.4](https://www.rfc-editor.org/rfc/rfc7517#section-4.4)). For `dir`, generate the key for its `enc`. ECDH-ES works on several curves, so it fails with `InvalidKey` here: generate an EC or X25519 key by curve instead. PBES2 passwords aren't generated.

## Publish only the public half

`jwkToPublic` removes the private members, such as `d` ([RFC 7518 §6.2.1](https://www.rfc-editor.org/rfc/rfc7518#section-6.2.1)). Publish or send only that public half: anyone who has the private key can sign or decrypt as you. An `oct` key has no public half: `jwkToPublic` fails with `UnsupportedAlgorithm`, and Rust's `Jwk::to_public` returns `None`.

`jwkToPem` and `jwkToDer` export a JWK in the format you name. `jwkFromPem` reads one PEM block and takes the structure from its label. In Rust these are `Jwk::to_pem`, `Jwk::to_der`, `Jwk::from_pem` and `Jwk::from_der`, with a `keys::KeyFormat`.

<Samples id="manage-keys/pem" />

DER has no label, so `jwkFromDer` always takes the format name, and DER of any other structure fails with `InvalidKey`: polyjose never guesses.

<Samples id="manage-keys/der" />

An imported key has no `alg`, because PEM and DER don't name a JOSE algorithm. Secret `oct` keys never go through PEM or DER, in either direction, so text from a PEM file can never become an HMAC key ([RFC 8725 §2.1](https://www.rfc-editor.org/rfc/rfc8725#section-2.1)).

## Thumbprints

A JWK Thumbprint ([RFC 7638](https://www.rfc-editor.org/rfc/rfc7638)) is a hash of a key's required members, so it identifies the key whatever else the JWK holds. `jwkThumbprint` uses SHA-256 unless you pass `SHA-384` or `SHA-512`; SHA-1 isn't offered. `jwkThumbprintUri` returns the same value as a URI ([RFC 9278](https://www.rfc-editor.org/rfc/rfc9278)). In Rust, use `Jwk::thumbprint_sha256` and `Jwk::thumbprint_uri_sha256`, or `thumbprint` and `thumbprint_uri` with a `jwk::ThumbprintHash`. Thumbprint public keys. The thumbprint of an `oct` key is a fast, unsalted hash of the secret, so never publish it or use it as a `kid`, and above all not for a password.

## Handle secrets

Private keys, secret `oct` keys, decrypted plaintext and verified payloads are secrets. On every platform:

- Never log a private or secret JWK, a verified or decrypted result, or the records that carry a key, such as `JwsSigner` and `JweRecipient`.
- When you are done with returned secret bytes, overwrite them: `fill(0)` on a `Uint8Array` in JavaScript, `fill(0)` on a `ByteArray` in Kotlin, and `resetBytes(in:)` on `Data` in Swift. In Rust, `to_der` and `to_pem` return `Zeroizing` values, which are wiped when dropped, and every `Jwk` is wiped on drop.

<Samples id="manage-keys/wipe" />

JavaScript results are plain objects, so printing one prints its secret bytes. The Kotlin and Swift records hide their secret fields when printed, and Rust's `Debug` output never shows key material. Strings can't be wiped on any platform: a JWK held as JSON text stays in memory until the runtime reuses it. [Security model › Secrets in memory](/security/model/#secrets-in-memory) explains what polyjose wipes and what it can't. To publish several public keys at once, see [JWK Sets](/guides/jwk-sets/).

The code on this page is compiled and run as tests against the polyjose source, on macOS, so it shows the API as it ships.

The polyjose Swift package calls the polyjose Rust core, which it links as a static XCFramework. iOS is its main target.

## Install

Add the package with Swift Package Manager, in `Package.swift` or in Xcode under **File › Add Package Dependencies**, and depend on the product `Polyjose`:

<Install platform="swift" />

- **iOS 16 or later, and macOS 13 or later.** Those are the minimums the package declares.
- **Swift 6.** The package's manifest needs Swift tools 6.0.
- **No other Rust static library in the same app.** polyjose links its own copy of the Rust standard library, so a second Rust static library can make the link fail with duplicate symbols.

## Sign your first token

These samples use RFC 7515's example P-256 key, from Appendix A.3. Its private part is printed in the RFC, so use it only to try things out.

<Sample platform="swift" id="start/swift-imports" />

A JWS needs a protected header with an `alg`. Here it is `ES256`, ECDSA with P-256 and SHA-256 (RFC 7518 §3.4). Keys are JWKs as JSON text; `privateKey` is the example key's JWK.

<Sample platform="swift" id="start/swift-first-sign" />

`token` is a JWS in the compact serialization: three base64url parts joined by dots (RFC 7515 §7.1).

## Verify it

Verifying always takes an explicit `allowedAlgs`, with no default, so leaving it out doesn't compile. polyjose never trusts the `alg` in the token's header on its own, and `none` is never accepted (RFC 8725 §3.1). `publicKey` is the same JWK without its private member `d`.

<Sample platform="swift" id="start/swift-first-verify" />

Printing `verified` shows the payload's length, not its bytes. Reading `verified.payload` still gives you the bytes, so when they are secret, don't log them, and wipe them once you are done: `resetBytes(in:)` on a `var` that holds them. `Data` is copy-on-write, so this wipes only bytes that no other copy shares.

## Handle an error

Calls are synchronous and throw a `PolyjoseError` when they fail. Its `code()` is one of a fixed set of strings, the same on every platform. Here the verifier accepts only `Ed25519`, so the ES256 token is refused before any cryptography runs:

Branch on `code()`, never on the message or the case name. [Errors](/concepts/errors/) lists every code and when it happens.

The code on this page is run as tests against the polyjose source: in Node.js, and the Web Worker sample in headless Chromium. So it shows the API as it ships.

`@polyjose/wasm` is the polyjose Rust core compiled to WebAssembly. It has the same API as [`@polyjose/node`](/start/node/), so moving between the two means changing the import.

## Install

The package is ESM only, and every call returns a Promise. The WebAssembly module loads on the first call: importing the package does nothing, and it never uses top-level await.

- **Tested:** polyjose's own tests run the package in Node.js 22.12 or later, in headless Chrome and in Cloudflare Workers (workerd).
- **Expected to work:** current Firefox and Safari, and bundlers that handle `new URL("…", import.meta.url)`, such as webpack 5, Vite and esbuild.
- **Untested:** Deno and Bun are not tested for 0.1.0. Both resolve the `node` or `default` condition.

### Serving the module

- **Content Security Policy.** A page with a CSP must allow WebAssembly compilation with `script-src 'wasm-unsafe-eval'`, and the fetch of `polyjose_wasm_bg.wasm` (`connect-src`). Without `'wasm-unsafe-eval'`, the first call rejects.
- **Serve the `.wasm` byte for byte,** as `application/wasm`. The browser entry fetches it with Subresource Integrity, so a server, CDN or bundler that rewrites the file makes the first call reject.

## Sign your first token

These samples use RFC 7515's example P-256 key, from Appendix A.3. Its private part is printed in the RFC, so use it only to try things out.

<Sample platform="web" id="start/js-imports" />

A JWS needs a protected header with an `alg`. Here it is `ES256`, ECDSA with P-256 and SHA-256 (RFC 7518 §3.4). Keys are JWKs, either as JSON text or as plain objects; `privateKey` is the example key's JWK.

<Sample platform="web" id="start/js-first-sign" />

`token` is a JWS in the compact serialization: three base64url parts joined by dots (RFC 7515 §7.1).

## Verify it

Verifying always takes an explicit `allowedAlgs`. polyjose never trusts the `alg` in the token's header on its own, and `none` is never accepted (RFC 8725 §3.1). `publicKey` is the same JWK without its private member `d`.

<Sample platform="web" id="start/js-first-verify" />

`verified.payload` is a plain `Uint8Array`, and printing `verified` prints it. When the payload is secret, don't log the result, and wipe the bytes with `verified.payload.fill(0)` once you are done with them.
